     9→# Phase 0: Foundation Layer
    10→
    11→## 0.1 Architecture Overview
    12→
    13→### Framework: CodeIgniter (Custom MVC)
    14→- **Entry Point**: `index.php` → loads `system/` core → routes to `application/controllers/`
    15→- **Routing**: `config/routes.php` — default_controller = `home`, no custom routes (all URL-based: `controller/method/param`)
    16→- **Base Controller Hierarchy**:
    17→
    18→```
    19→CI_Controller (CodeIgniter System)
    20→  └── MY_Controller (application/core/MY_Controller.php)
    21→        ├── Guest_controller   → Public pages (login, register, home, etc.) — optional auth
    22→        ├── Patient_contoller  → Patient-only pages
    23→        ├── Doctor_controller  → Doctor-only pages
    24→        ├── Hospital_contoller → Hospital-only pages
    25→        ├── Reception_contoller→ Receptionist-only pages
    26→        ├── Assistant_controller→ Assistant-only pages
    27→        ├── Admin_contoller    → Admin-only pages
    28→        └── Pharmacist_contoller→ Pharmacist-only pages
    29→```
    30→
    31→### Guard Logic (in each role controller's `__construct`):
    32→1. Check `session->userdata('user_login')` exists → if not, redirect to `auth/login`
    33→2. Check `role` matches the controller's role → if not, redirect to `auth/login`
    34→3. Re-verify user not blocked via `user->check_auth_after_login()` → if blocked, logout with flash message
    35→4. Load common data: `$view_data['user']`, `$view_data['notifications']` (last 7), `$view_data['notificationsCount']`
    36→
    37→### Special Case — Receptionist Controller:
    38→- Loads additional: `receptionist` model, `doctor` model
    39→- Sets `$this->user_data->doctor_id` from `receptionist->get_by_user_id()` — receptionist is ALWAYS linked to a doctor
    40→- Sets `$this->doctor_data` = doctor's full profile (used in views)
    41→
    42→### Special Case — Guest Controller:
    43→- Auth is OPTIONAL — loads user data if session exists, empty array if not
    44→- Used by: Home, Doctors, Hospitals, Blog, About, Contact, Privacy, Terms, Auth, Search, etc.
    45→
    46→### MVC Flow Per Request:
    47→```
    48→URL → Router → Controller::method()
    49→  → Load Model(s)
    50→  → Query Database
    51→  → Set $view_data
    52→  → Load View (wrapped in Layout)
    53→    → Layout includes: navbar, sidebar, content area, footer
    54→    → Content area = specific view file
    55→```

   128→
   129→### Located in: `core/MY_Controller.php`
   130→
   131→### Alert/Response Helpers:
   132→| Method | Purpose | Flash Keys |
   133→|---|---|---|
   134→| `_alertSuccessResponce($success, $msg, $fail_msg, $url)` | Success/error redirect | feedback, feedback_class (success/error) |
   135→| `_alertInfoResponce(...)` | Info/error redirect | feedback, feedback_class (info/error) |
   136→| `_alertWarningResponce(...)` | Warning/error redirect | feedback, feedback_class (alert/error) |
   137→
   138→### Encryption Helpers:
   139→| Method | Purpose |
   140→|---|---|
   141→| `encrypted_text($plain)` | AES-128-CBC encrypt, URL-safe base64 (`.`, `-`, `~` replacing `+`, `=`, `/`) |
   142→| `decrypted_text($encrypted)` | Reverse of above |
   143→| Used for: Email verification tokens, forgot password tokens |
   144→
   145→### Email Helper:
   146→| Method | Purpose |
   147→|---|---|
   148→| `send_mail($to, $subject, $msg)` | Send HTML email via SMTP. From: EMAIL_FROM/EMAIL_NAME. Returns true/false. |
   149→| Email templates: Built as inline HTML strings in Auth controller |
   150→
   151→### File Upload Helpers:
   152→| Method | Purpose |
   153→|---|---|
   154→| `_upload_files($path, $title, $control_name)` | Upload multiple images. Allowed: jpg, jpeg, gif, png. Max: 2000KB. Returns JSON array of filenames. |
   155→| `_upload_file($path, $title, $control_name)` | Upload single image. Same restrictions. Returns `{status, file_name}` or `{status, upload_error}`. |
   156→| `_upload_pdf($path, $title, $control_name)` | Upload PDF/XLSX/XLS. Max 2000KB. Returns same format. |
   157→| `_generate_thumb($source_path, $target_path, $file)` | Generate 300x300 thumbnail. Returns `filename_thumb.ext`. Uses GD2 library. |
   158→| `_generate_multiple_thumb(...)` | Loop of above for array of files. |
   159→| File naming: `{title}_{timestamp}_{uniqid}.{ext}` |
   160→
   161→### Other Helpers:
   162→| Method | Purpose |
   163→|---|---|
   164→| `logout()` | Unset `user_login` session, redirect to `auth/login` |
   165→| `next_available_booking_days($days, $holidays)` | Generate array of next N available dates, excluding holidays. Used for booking date selection. |
   166→| `sendMobileMessage($mobile, $message)` | HTTP GET to SMS gateway. URL: `sms.soft-techsolutions.com`. Sender ID: NTFSMS. |
   167→| `_generateSeoURL($string, $wordLimit)` | Generate URL-safe slug from string. Used for blog permalinks. |
   168→| `dump($var)` | var_dump with `<pre>` wrapper (debug) |

   170→### Standalone Helper: `helpers/date_formater_helper.php`

   621→## 0.5 Authentication Flow — Complete
   622→
   623→### Registration Flow:
   624→```
   625→1. GET /auth/register?type=dr OR ?type=patient
   626→   → Loads register.php view
   627→   → Only doctor and patient can self-register (other roles created by admin)
   628→
   629→2. POST /auth/signup?type=dr OR ?type=patient
   630→   → Validates: name, email(unique), password(min 6), confirm_password(match), mobile_no, gender, terms
   631→   → role = 'doctor' or 'patient' based on ?type
   632→   → status = 'Pending' (needs mobile verification)
   633→   → password = SHA256(password)
   634→   → Creates user in DB
   635→   → Sends welcome SMS with credentials
   636→   → Redirects to /auth/login with flash message
   637→   → NOTE: Email verification code exists but is COMMENTED OUT
   638→```
   639→
   640→### Login Flow:
   641→```
   642→1. GET /auth/login
   643→   → If already logged in → redirect to role-specific dashboard
   644→   → Loads login.php view
   645→
   646→2. POST /auth/auth_login
   647→   → Validates: email, password(min 6)
   648→   → password = SHA256(password)
   649→   → Check: user->check_auth($logData)
   650→   → If status = 'Active':
   651→      → Set session 'user_login' with: {id, name, email, role, status, mobile_no, profile_img}
   652→      → Redirect by role:
   653→         doctor → /doctor/dashboard
   654→         patient → /home (NOTE: inconsistent — register says /home, login says /appointment)
   655→         receptionist → /receptionist/dashboard
   656→         hospital → /hospital/dashboard
   657→         admin → /admin/dashboard
   658→         assistant → /assistant/dashboard
   659→         pharmacist → /pharmacist/pharmacist/listPrescriptions
   660→   → If status = 'Pending':
   661→      → Set session 'verify_data' with user data
   662→      → Redirect to /auth/verify_mobile
   663→   → If status = 'Block':
   664→      → Flash error "You are Blocked"
   665→      → Redirect to /auth/login
   666→   → If credentials invalid:
   667→      → Flash error "Email or Password is invalid"
   668→      → Redirect back to login
   669→   → Remember Me: extends session cookie to 7 days
   670→```
   671→
   672→### Mobile OTP Verification Flow:
   673→```
   674→1. GET /auth/verify_mobile (only if session 'verify_data' exists)
   675→   → Shows OTP input form
   676→
   677→2. POST /auth/sendotp_mobile_verify
   678→   → Generates 6-digit random OTP
   679→   → Sends SMS: "Dear User, {otp} is your Doctorooms OTP code for verification."
   680→   → Stores in session 'mobile_verification_data': {mobile_no, otp, date}
   681→
   682→3. POST /auth/verify_mobile_submit
   683→   → Checks OTP expiry: 180 seconds (3 minutes)
   684→   → Compares OTP
   685→   → If match:
   686→      → Updates user: status='Active', mobile_verified_at=now()
   687→      → Creates full session
   688→      → Redirects to /auth/login (which then redirects to dashboard)
   689→   → If mismatch: flash error, redirect back
   690→   → If expired: unset sessions, flash error, redirect to login
   691→```
   692→
   693→### Forgot Password Flow:
   694→```
   695→1. GET /auth/forgot_password → Shows mobile number form
   696→
   697→2. POST /auth/forgot_submit
   698→   → Validates mobile number exists in DB
   699→   → Stores 'forgot_data' session: {mobile, created_at}
   700→   → Redirects to OTP verification
   701→
   702→3. POST /auth/forgot_password_send_otp
   703→   → Generates OTP, sends SMS
   704→   → Stores 'forgot_password_verification_data': {mobile_no, otp, date}
   705→
   706→4. POST /auth/forgot_password_mobile_verification_submit
   707→   → Checks OTP expiry: 180 seconds
   708→   → If match: stores 'generate_password_data', redirects to new password form
   709→
   710→5. GET /auth/generate_new_password → Shows new password form
   711→
   712→6. POST /auth/generate_new_password_submit
   713→   → Validates: new_password(min 6), confirm_password(match)
   714→   → Hashes new password, updates user
   715→   → Unsets sessions, redirects to login
   716→   → OTP valid for 300 seconds (5 minutes) at this stage
   717→```

   721→## 0.6 Role & Permission System
   722→
   723→### Role Hierarchy & Access:
   724→| Role | Self-Register | Created By | Dashboard URL | Guard Class |
   725→|---|---|---|---|---|
   726→| Admin | No | Pre-seeded | /admin/dashboard | Admin_contoller |
   727→| Doctor | Yes (?type=dr) | Self/Admin | /doctor/dashboard | Doctor_controller |
   728→| Patient | Yes (?type=patient) | Self | /home or /appointment | Patient_contoller |
   729→| Hospital | No | Admin | /hospital/dashboard | Hospital_contoller |
   730→| Receptionist | No | Doctor/Admin | /receptionist/dashboard | Reception_contoller |
   731→| Assistant | No | Doctor/Admin | /assistant/dashboard | Assistant_controller |
   732→| Pharmacist | No | Doctor/Admin | /pharmacist/pharmacist/listPrescriptions | Pharmacist_contoller |
   733→
   734→### Guard Logic (per role controller):
   735→1. Session must exist with 'user_login'
   736→2. Role must match controller's expected role
   737→3. User must not be blocked (re-checks DB on every request)
   738→4. Loads notifications (last 7 days) and count
   739→
   740→### Shared Data in $view_data (set in constructor):
   741→- `$view_data['user']` — Full user object from DB
   742→- `$view_data['notifications']` — Array of recent notifications
   743→- `$view_data['notificationsCount']` — Count of notifications
   744→- (Receptionist only) `$view_data['doctor_data']` — Associated doctor's profile
