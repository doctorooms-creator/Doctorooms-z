    35→## 1. Executive Summary
    36→
    37→The current prescription system is a **flat single-page form** that creates a prescription in one shot. The legacy PHP system uses a **6-step AJAX stepper wizard** where two different roles (Assistant and Doctor) complete different steps. This plan rebuilds the entire prescription workflow to match the legacy system's UX while leveraging the modern Next.js stack.
    38→
    39→### Key Changes at a Glance
    40→
    41→| Aspect | Current (Broken) | Planned (Legacy Match) |
    42→|--------|------------------|------------------------|
    43→| Prescription creation | Single flat form | 6-step stepper wizard (AJAX, no page reload) |
    44→| Roles | Doctor only | Assistant (Steps 1-2) + Doctor (Steps 3-6) |
    45→| Complaints | None | C/O with multi-language (local + English) |
    46→| Vitals | Flat fields in prescription | Step 2 — separate entry by assistant |
    47→| Medicine timing | Booleans (morning/afternoon/evening) | Numbers (tablet count per time slot) |
    48→| Medicine dose | Single string | JSON array of options (tag input) |
    49→| Findings | None | NEW — auto-fill medicines by finding |
    50→| Suggestions | Free text | Auto-linked from Category → Complaint → Suggestion hierarchy |
    51→| Labels | No units, no showUnit toggle | Units + `showUnit` boolean per label |
    52→| Tables | No custom templates | Doctor-built table templates with preview |
    53→| Print | Basic template | Custom header OR full header image, C/O section, tables, next visit |

    57→## 2. Core Concepts & Mental Model
    58→
    59→### 2.1 The Two-Phase Workflow
    60→
    61→```
    62→┌─────────────────────────────────────────────────────────────────┐
    63→│                    PATIENT FLOW                                  │
    64→│                                                                  │
    65→│  Patient arrives → Sits OUTSIDE cabin → Goes INSIDE cabin       │
    66→│                                                                  │
    67→│  ┌──────────────────┐     ┌──────────────────────────────┐     │
    68→│  │   ASSISTANT      │     │         DOCTOR               │     │
    69→│  │   (Outside)      │     │         (Inside)             │     │
    70→│  │                  │     │                              │     │
    71→│  │ Step 1: Complaints│     │ Step 3: Diagnosis Tables    │     │
    72→│  │ Step 2: Vitals    │     │ Step 4: Medicines           │     │
    73→│  │                  │     │ Step 5: Suggestions          │     │
    74→│  │                  │     │ Step 6: Finish & Print       │     │
    75→│  └──────────────────┘     └──────────────────────────────┘     │
    76→│                                                                  │
    77→└─────────────────────────────────────────────────────────────────┘
    78→```
    79→
    80→### 2.2 Multi-Language Dual-Field Pattern
    81→
    82→**Every user-facing text entity uses TWO fields:**
    83→
    84→```
    85→┌─────────────────────────┬──────────────────────────┐
    86→│  Field (Primary)        │  FieldEn (English)        │
    87→├─────────────────────────┼──────────────────────────┤
    88→│  "તાવો આવે છે" (Gujarati)  │  "Fever" (English)        │
    89→│  "સરદી લાગે છે"          │  "Cold"                   │
    90→│  "પેટમાં દુખાવો"          │  "Stomach Pain"           │
    91→└─────────────────────────┴──────────────────────────┘
    92→
    93→Usage:
    94→  - SELECTOR UI (stepper, dropdowns, tags) → Shows PRIMARY (local language)
    95→  - PRINT OUTPUT (prescription PDF/print)  → Shows ENGLISH version
    96→```
    97→
    98→### 2.3 Suggestion Auto-Linking Hierarchy
    99→
   100→```
   101→Category (શરીર / Body)
   102→  └── Complaint (તાવો / Fever)  ← Selected in Step 1
   103→        ├── Suggestion 1: "Drink plenty of water"
   104→        ├── Suggestion 2: "Take rest for 3 days"
   105→        └── Suggestion 3: "Avoid cold food"
   106→
   107→  └── Complaint (સરદી / Cold)  ← Also selected in Step 1
   108→        ├── Suggestion 1: "Steam inhalation 2x daily"
   109→        └── Suggestion 2: "Warm water gargling"
   110→
   111→In Step 5: Only suggestions linked to SELECTED complaints appear.
   112→```
   113→
   114→### 2.4 Findings → Medicine Auto-Fill
   115→
   116→```
   117→Doctor creates Finding: "Viral Fever"
   118→  └── Links 5 medicines to it:
   119→        ├── Paracetamol 500mg — 1-0-1
   120→        ├── Azithromycin 500mg — 1-0-0 (3 days)
   121→        ├── Cetirizine 10mg — 0-0-1
   122→        ├── Pan D — 1-0-0
   123→        └── Multivitamin — 1-0-1
   124→
   125→During Rx Step 4: Doctor selects "Viral Fever" from dropdown
   126→  → All 5 medicines auto-fill with their doses and timings
   127→  → Doctor can modify any individual medicine before saving
   128→```

   490→## 5. The 6-Step Stepper Wizard
   491→
   492→### 5.1 Step Overview
   493→
   494→| Step | Title | Actor | Description |
   495→|------|-------|-------|-------------|
   496→| 1 | **Chief Complaints (C/O)** | Assistant | Select complaints from master (shown in primary/local language). Multi-select with search. |
   497→| 2 | **Vitals & Labels** | Assistant | Enter patient vitals using Label Master. Weight, BP, Temperature + any custom labels. |
   498→| 3 | **Diagnosis Tables** | Doctor | Add custom tables (ultrasound reports, lab data). Can use pre-built templates or create ad-hoc. |
   499→| 4 | **Medicines (Rx)** | Doctor | Add medicines manually OR auto-fill via Findings dropdown. Edit any field. |
   500→| 5 | **Suggestions / Advice** | Doctor | Suggestions auto-populated based on selected complaints (from Step 1). Click to select. |
   501→| 6 | **Finish & Print** | Doctor | Review all data. Set next visit date. Save & Print. |
   502→
   503→### 5.2 Stepper UI Behavior
   504→
   505→```
   506→┌─────────────────────────────────────────────────────────────┐
   507→│  ① Complaints  →  ② Vitals  →  ③ Tables  →  ④ Rx  →  ⑤ Advice  →  ⑥ Finish  │
   508→│  ═══════════     ────────    ────────   ───────   ────────    ────────  │
   509→│  (completed)     (current)  (pending)  (pending)  (pending)   (pending)  │
   510→└─────────────────────────────────────────────────────────────┘
   511→
   512→RULES:
   513→- Steps 1-2: Visible & editable by ASSISTANT role
   514→- Steps 3-6: Visible & editable by DOCTOR role
   515→- All 6 steps visible as a progress bar at the top
   516→- Current step content swaps below WITHOUT page reload (React state)
   517→- Each step has a "Save & Continue" button that persists to DB via API
   518→- Steps 1-2 are auto-saved when assistant submits
   519→- Doctor sees read-only summary of Steps 1-2 at the top when entering Step 3
   520→- Back navigation allowed (go back to previous step, data preserved)
   521→- Steps are NOT strictly sequential for doctor — can jump to any step 3-6
   522→```
   523→

   735→## 6. Two-Phase Workflow (Assistant + Doctor)
   736→
   737→### 6.1 How It Works
   738→
   739→```
   740→ASSISTANT FLOW:
   741→1. Assistant opens their dashboard → sees "Pending Prescriptions" queue
   742→2. Clicks on an approved/visited appointment
   743→3. Lands on Step 1 (Complaints) of the stepper
   744→4. Selects complaints, enters vitals (Steps 1-2)
   745→5. Clicks "Submit to Doctor" → prescription saved with status "Draft"
   746→6. Prescription appears in Doctor's queue
   747→
   748→DOCTOR FLOW:
   749→1. Doctor opens their dashboard → sees prescriptions ready for completion
   750→2. Clicks on a prescription → lands on Step 3 (Tables)
   751→3. Steps 1-2 shown as READ-ONLY summary at top
   752→4. Doctor completes Steps 3-6
   753→5. On Step 6, clicks "Save & Print" → prescription finalized
   754→```

   765→- If booking already has a Draft prescription (assistant completed Steps 1-2), load that prescription and start at Step 3

   785→

   789→4. **Snapshot records** (PMedicine, PLabel, PSuggestion, etc.): Store both versions at the time of prescription creation.

   895→
   896→### 9.1 Architecture
   897→
   898→```
   899→FindingsMaster (the finding name)
   900→  │
   901→  ├── FindingsMedicine (join records)
   902→  │     ├── medicineId → DoctorMedicine (which medicine)
   903→  │     ├── dose → override dose (blank = use master default)
   904→  │     ├── morning → override morning count (0 = use master default)
   905→  │     ├── afternoon → override afternoon count
   906→  │     ├── evening → override evening count
   907→  │     ├── tab → override days (0 = use master default)
   908→  │     └── description → override description
   909→  │

   913→### 9.2 Auto-Fill Flow in Step 4
   914→
   915→```
   916→1. Doctor opens Step 4 (Medicines)
   917→2. Sees dropdown: "Select Finding"
   918→3. Selects "Viral Fever"
   919→4. System fetches FindingsMedicine records for this finding
   920→5. For each linked medicine:
   921→   a. Look up DoctorMedicine by medicineId
   922→   b. Get name, dose array from DoctorMedicine
   923→   c. Use FindingsMedicine overrides for morning/afternoon/evening/tab/dose/description
   924→   d. If override is 0 or blank, fall back to DoctorMedicine defaults
   925→   e. Pre-populate medicine row in the stepper
   926→6. Doctor can:
   927→   - Select ANOTHER finding (adds more medicines, skips duplicates by medicineId)
   928→   - Edit any pre-populated value
   929→   - Remove any pre-populated medicine
   930→   - Add medicines manually
   931→```

  1335→
  1336→```typescript
  1337→// src/lib/prescription-store.ts
  1338→
  1339→interface PrescriptionStore {
  1340→  // Navigation
  1341→  currentStep: number
  1342→  setCurrentStep: (step: number) => void
  1343→  goToNext: () => void
  1344→  goToPrev: () => void
  1345→
  1346→  // Prescription ID (created on init)
  1347→  prescriptionId: string | null
  1348→  setPrescriptionId: (id: string) => void
  1349→
  1350→  // Booking info (passed as prop or from URL)
  1351→  bookingId: string
  1352→  setBookingId: (id: string) => void
  1353→
  1354→  // Step 1: Complaints
  1355→  selectedComplaintIds: string[]
  1356→  setSelectedComplaintIds: (ids: string[]) => void
  1357→  toggleComplaint: (id: string) => void
  1358→
  1359→  // Step 2: Vitals
  1360→  vitals: { weight: string; bp: string; temperature: string; pulse: string; spo2: string }
  1361→  setVitals: (vitals: Partial<Vitals>) => void
  1362→  labelValues: { labelId: string; value: string }[]
  1363→  setLabelValue: (labelId: string, value: string) => void
  1364→
  1365→  // Step 3: Tables
  1366→  tables: TableData[]
  1367→  setTables: (tables: TableData[]) => void
  1368→  addTable: (table: TableData) => void
  1369→  removeTable: (index: number) => void
  1370→  updateTable: (index: number, table: TableData) => void
  1371→
  1372→  // Step 4: Medicines
  1373→  medicines: MedicineRow[]
  1374→  setMedicines: (medicines: MedicineRow[]) => void
  1375→  addMedicine: (medicine: MedicineRow) => void
  1376→  removeMedicine: (index: number) => void
  1377→  updateMedicine: (index: number, medicine: Partial<MedicineRow>) => void
  1378→  autoFillFromFinding: (findingId: string, medicines: MedicineRow[]) => void
  1379→
  1380→  // Step 5: Suggestions
  1381→  selectedSuggestionIds: string[]
  1382→  setSelectedSuggestionIds: (ids: string[]) => void
  1383→  toggleSuggestion: (id: string) => void
  1384→  customSuggestions: { question: string; suggestions: string }[]
  1385→  addCustomSuggestion: (s: { question: string; suggestions: string }) => void
  1386→
  1387→  // Step 6
  1388→  nextVisit: Date | null
  1389→  setNextVisit: (date: Date | null) => void
  1390→
  1391→  // Loading states
  1392→  isSaving: boolean
  1393→  setIsSaving: (saving: boolean) => void
  1394→
  1395→  // Reset
  1396→  reset: () => void
  1397→}
  1398→```

  1400→### 16.2 Data Flow
  1401→
  1402→```
  1403→1. Component mounts → Read prescriptionId from URL or create new via /api/prescription/init

  1405→3. User interacts with step components → store updates
  1406→4. "Save & Continue" → POST to step-specific API → store persists

  1555→## 18. Migration Strategy for Existing Data
  1556→
  1557→### 18.1 Morning/Afternoon/Evening: Boolean → Int
  1558→
  1559→```sql
  1560→-- Migrate PMedicine
  1561→UPDATE "PMedicine" SET "morning" = CASE WHEN "morning" = true THEN 1 ELSE 0 END;
  1562→UPDATE "PMedicine" SET "afternoon" = CASE WHEN "afternoon" = true THEN 1 ELSE 0 END;
  1563→UPDATE "PMedicine" SET "evening" = CASE WHEN "evening" = true THEN 1 ELSE 0 END;
  1564→
  1565→-- Migrate DoctorMedicine (was String type, values like "after food" or empty)
  1566→-- This is trickier — need to set reasonable defaults
  1567→UPDATE "DoctorMedicine" SET "morning" = 1 WHERE "morning" != '';
  1568→UPDATE "DoctorMedicine" SET "afternoon" = 1 WHERE "afternoon" != '';
  1569→UPDATE "DoctorMedicine" SET "evening" = 1 WHERE "evening" != '';
  1570→UPDATE "DoctorMedicine" SET "morning" = 0 WHERE "morning" = '';
  1571→UPDATE "DoctorMedicine" SET "afternoon" = 0 WHERE "afternoon" = '';
  1572→UPDATE "DoctorMedicine" SET "evening" = 0 WHERE "evening" = '';
  1573→```
  1574→
  1575→### 18.2 DoctorMedicine Dose: String → JSON Array
  1576→
  1577→```sql
  1578→-- Wrap existing dose string into a JSON array
  1579→UPDATE "DoctorMedicine" 
  1580→SET "dose" = '[' || '"' || REPLACE("dose", '"', '\"') || '"]' 
  1581→WHERE "dose" != '' AND "dose" != '[]';
  1582→
  1583→-- Set empty to empty array
  1584→UPDATE "DoctorMedicine" SET "dose" = '[]' WHERE "dose" = '' OR "dose" IS NULL;
  1585→```
  1586→
  1587→### 18.3 New Fields with Defaults
  1588→
  1589→All new fields have default values (`@default("")`, `@default(0)`, `@default(false)`), so existing rows will migrate cleanly with `db:push`.

  1593→## 19. Edge Cases & Gotchas
  1594→
  1595→### 19.1 Critical
  1596→
  1597→| # | Edge Case | Handling |
  1598→|---|-----------|----------|
  1599→| E1 | **Duplicate medicines from multiple findings** | When auto-filling from 2nd finding, skip medicines already in the list (match by `medicineId` from DoctorMedicine) |
  1600→| E2 | **Complaint deleted after being used in Rx** | Never hard-delete master data. Use soft delete (status=Inactive). PCo records keep the `coId` reference — snapshot the text at Rx creation time |
  1601→| E3 | **DoctorMedicine dose array empty** | If dose array is `[]`, show a plain text input instead of dropdown in Step 4 |
  1602→| E4 | **Prescription init when draft already exists** | Check for existing Draft prescription for the bookingId. If found, load it instead of creating new |
  1603→| E5 | **Concurrent editing** | Assistant and Doctor shouldn't edit same prescription simultaneously. Lock prescription when doctor opens it (or at minimum, show warning) |
  1604→| E6 | **Print with no data** | Each section in print is conditional — only shown if data exists |
  1605→| E7 | **Category deleted but complaints exist** | Complaints can exist without a category (categoryId nullable). Show them under "Uncategorized" in stepper |
  1606→
  1607→### 19.2 UX
  1608→
  1609→| # | Edge Case | Handling |
  1610→|---|-----------|----------|
  1611→| E8 | **Mobile stepper** | On mobile, step indicator shows icons only (numbers). Step content is full-width scrollable |
  1612→| E9 | **Large findings list** | Findings dropdown should be searchable (typeahead) |
  1613→| E10 | **Many complaints** | Step 1 complaints should be searchable and grouped with collapsible categories |
  1614→| E11 | **Table with many rows/cols** | Tables should be horizontally scrollable on mobile |
  1615→| E12 | **Medicine name not found in master** | Allow free-text medicine name in Step 4 (not all medicines need to be in master) |
