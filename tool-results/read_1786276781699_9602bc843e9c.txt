     1→# Phase 5: Receptionist Dashboard
     2→## Overview
     3→The Receptionist module is tied to a specific **doctor** via the `receptionist` table (`user_id` → `doctor_id`). Every receptionist operates **within the scope of their assigned doctor**. The base controller is `Reception_contoller` (note: typo in original code). Layout: `master_page_receptionist.php`. AdminLTE 2.4.0 skin-black-light theme.
     4→
     5→**Sidebar Navigation:**
     6→1. Dashboard
     7→2. Blog
     8→3. Appointments
     9→4. Manage Schedule
    10→5. Medicine List

    65→- **GET.** Loads doctor info, next holidays (JSON for datepicker)

    68→#### Method `book()` — Submit New Appointment
    69→- **POST.** Validation rule: `booking_by_receptionist`
    70→- Logic:
    71→  1. Gets doctor info, checks daily limit (commented out but code present)
    72→  2. Looks up user by mobile via `$user->get_by_mobile($data['mobile'])`
    73→  3. Sets `doctor_id`, `user_id` (or null), `status=APPROVE`, `appointment_charge` from Config_model, `booking_type=BY_RECEPTIONIST`
    74→  4. Generates booking number: `APMT-{increment}` via `generateBookingNumber()`
    75→  5. Creates booking record
    76→  6. Sends notification to doctor AND patient (if user_id exists)
    77→  7. Sends SMS via `sendMobileMessage()`

    79→- On validation failure: reloads book form with holidays

    81→#### Method `get_appointment_table()` — AJAX Table Refresh

    86→#### Method `show($id)` — View Single Appointment

    92→#### Method `approve($id)` — Approve Appointment
    93→- **GET.** Status guards: not VISITED, not REJECTED

    98→
    99→#### Method `visited($id)` — Mark as Visited
   100→- **GET.** Status guards: not REJECTED, not PENDING, not EXTEND
   101→- Updates status to `VISITED`
   102→- Sends notifications to: doctor, patient
   103→- Sends SMS to patient
   104→- Redirect: `receptionist/appointment?status=Visited`
   105→
   106→#### Method `reject($id)` — Reject Appointment
   107→- **GET.** Status guard: not VISITED
   108→- Updates status to `REJECTED`
   109→- Sends notifications to: doctor, patient
   110→- Redirect: `receptionist/appointment?status=Rejected`
   111→
   112→#### Method `extend($id)` — Extend Appointment

   875→## Architecture Notes
   876→- **Two separate prescription systems:** Simple (`prescriptions` table) and Complex (`prescription` table + 7 related tables). The Ajax Prescription wizard is the primary/active system.
   877→- **All three roles** are scoped to a single doctor via their respective linkage tables
   878→- **Code duplication:** Profile, Notifications, and Post controllers are near-identical across all three modules (only model names and URLs differ)
   879→- **Inconsistent URL routing:** Some controllers use `$this->input->get('status')` while AJAX endpoints use relative URLs that may not resolve correctly
   880→- **Hardcoded Google Analytics** appears in all three master layouts
