   589→  1555→## 18. Migration Strategy for Existing Data
   590→  1556→
   591→  1557→### 18.1 Morning/Afternoon/Evening: Boolean → Int
   592→  1558→
   593→  1559→```sql
   594→  1560→-- Migrate PMedicine
   595→  1561→UPDATE "PMedicine" SET "morning" = CASE WHEN "morning" = true THEN 1 ELSE 0 END;
   596→  1562→UPDATE "PMedicine" SET "afternoon" = CASE WHEN "afternoon" = true THEN 1 ELSE 0 END;
   597→  1563→UPDATE "PMedicine" SET "evening" = CASE WHEN "evening" = true THEN 1 ELSE 0 END;
   598→  1564→
   599→  1565→-- Migrate DoctorMedicine (was String type, values like "after food" or empty)
   600→  1566→-- This is trickier — need to set reasonable defaults
   601→  1567→UPDATE "DoctorMedicine" SET "morning" = 1 WHERE "morning" != '';
   602→  1568→UPDATE "DoctorMedicine" SET "afternoon" = 1 WHERE "afternoon" != '';
   603→  1569→UPDATE "DoctorMedicine" SET "evening" = 1 WHERE "evening" != '';
   604→  1570→UPDATE "DoctorMedicine" SET "morning" = 0 WHERE "morning" = '';
   605→  1571→UPDATE "DoctorMedicine" SET "afternoon" = 0 WHERE "afternoon" = '';
   606→  1572→UPDATE "DoctorMedicine" SET "evening" = 0 WHERE "evening" = '';
   607→  1573→```
   608→  1574→
   609→  1575→### 18.2 DoctorMedicine Dose: String → JSON Array
   610→  1576→
   611→  1577→```sql
   612→  1578→-- Wrap existing dose string into a JSON array
   613→  1579→UPDATE "DoctorMedicine" 
   614→  1580→SET "dose" = '[' || '"' || REPLACE("dose", '"', '\"') || '"]' 
   615→  1581→WHERE "dose" != '' AND "dose" != '[]';
   616→  1582→
   617→  1583→-- Set empty to empty array
   618→  1584→UPDATE "DoctorMedicine" SET "dose" = '[]' WHERE "dose" = '' OR "dose" IS NULL;
   619→  1585→```
   620→  1586→
   621→  1587→### 18.3 New Fields with Defaults
   622→  1588→
   623→  1589→All new fields have default values (`@default("")`, `@default(0)`, `@default(false)`), so existing rows will migrate cleanly with `db:push`.

   627→  1593→## 19. Edge Cases & Gotchas
   628→  1594→
   629→  1595→### 19.1 Critical
   630→  1596→
   631→  1597→| # | Edge Case | Handling |
   632→  1598→|---|-----------|----------|
   633→  1599→| E1 | **Duplicate medicines from multiple findings** | When auto-filling from 2nd finding, skip medicines already in the list (match by `medicineId` from DoctorMedicine) |
   634→  1600→| E2 | **Complaint deleted after being used in Rx** | Never hard-delete master data. Use soft delete (status=Inactive). PCo records keep the `coId` reference — snapshot the text at Rx creation time |
   635→  1601→| E3 | **DoctorMedicine dose array empty** | If dose array is `[]`, show a plain text input instead of dropdown in Step 4 |
   636→  1602→| E4 | **Prescription init when draft already exists** | Check for existing Draft prescription for the bookingId. If found, load it instead of creating new |
   637→  1603→| E5 | **Concurrent editing** | Assistant and Doctor shouldn't edit same prescription simultaneously. Lock prescription when doctor opens it (or at minimum, show warning) |
   638→  1604→| E6 | **Print with no data** | Each section in print is conditional — only shown if data exists |
   639→  1605→| E7 | **Category deleted but complaints exist** | Complaints can exist without a category (categoryId nullable). Show them under "Uncategorized" in stepper |
