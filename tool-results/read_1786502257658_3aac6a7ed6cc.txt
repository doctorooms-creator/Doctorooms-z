   894→## 9. Findings Master System
   895→
   896→### 9.1 Architecture
   897→
   898→```
   899→FindingsMaster (the finding name)
   900→  │
   901→  ├── FindingsMedicine (join records)
   902→  │     ├── medicineId → DoctorMedicine (which medicine)
   903→  │     ├── dose → override dose (blank = use master default)
   904→  │     ├── morning → override morning count (0 = use master default)
   905→  │     ├── afternoon → override afternoon count
   906→  │     ├── evening → override evening count
   907→  │     ├── tab → override days (0 = use master default)
   908→  │     └── description → override description
   909→  │
   910→  └── Used in Step 4 of stepper
   911→```
   912→
   913→### 9.2 Auto-Fill Flow in Step 4
   914→
   915→```
   916→1. Doctor opens Step 4 (Medicines)
   917→2. Sees dropdown: "Select Finding"
   918→3. Selects "Viral Fever"
   919→4. System fetches FindingsMedicine records for this finding
   920→5. For each linked medicine:
   921→   a. Look up DoctorMedicine by medicineId
   922→   b. Get name, dose array from DoctorMedicine
   923→   c. Use FindingsMedicine overrides for morning/afternoon/evening/tab/dose/description
   924→   d. If override is 0 or blank, fall back to DoctorMedicine defaults
   925→   e. Pre-populate medicine row in the stepper
   926→6. Doctor can:
   927→   - Select ANOTHER finding (adds more medicines, skips duplicates by medicineId)
   928→   - Edit any pre-populated value
   929→   - Remove any pre-populated medicine
   930→   - Add medicines manually
   931→```

  1555→## 18. Migration Strategy for Existing Data
  1556→
  1557→### 18.1 Morning/Afternoon/Evening: Boolean → Int
  1558→
  1559→```sql
  1560→-- Migrate PMedicine
  1561→UPDATE "PMedicine" SET "morning" = CASE WHEN "morning" = true THEN 1 ELSE 0 END;
  1562→UPDATE "PMedicine" SET "afternoon" = CASE WHEN "afternoon" = true THEN 1 ELSE 0 END;
  1563→UPDATE "PMedicine" SET "evening" = CASE WHEN "evening" = true THEN 1 ELSE 0 END;
  1564→
  1565→-- Migrate DoctorMedicine (was String type, values like "after food" or empty)
  1566→-- This is trickier — need to set reasonable defaults
  1567→UPDATE "DoctorMedicine" SET "morning" = 1 WHERE "morning" != '';
  1568→UPDATE "DoctorMedicine" SET "afternoon" = 1 WHERE "afternoon" != '';
  1569→UPDATE "DoctorMedicine" SET "evening" = 1 WHERE "evening" != '';
  1570→UPDATE "DoctorMedicine" SET "morning" = 0 WHERE "morning" = '';
  1571→UPDATE "DoctorMedicine" SET "afternoon" = 0 WHERE "afternoon" = '';
  1572→UPDATE "DoctorMedicine" SET "evening" = 0 WHERE "evening" = '';
  1573→```
  1574→
  1575→### 18.2 DoctorMedicine Dose: String → JSON Array
  1576→
  1577→```sql
  1578→-- Wrap existing dose string into a JSON array
  1579→UPDATE "DoctorMedicine" 
  1580→SET "dose" = '[' || '"' || REPLACE("dose", '"', '\"') || '"]' 
  1581→WHERE "dose" != '' AND "dose" != '[]';
  1582→
  1583→-- Set empty to empty array
  1584→UPDATE "DoctorMedicine" SET "dose" = '[]' WHERE "dose" = '' OR "dose" IS NULL;
  1585→```
  1586→
  1587→### 18.3 New Fields with Defaults
  1588→
  1589→All new fields have default values (`@default("")`, `@default(0)`, `@default(false)`), so existing rows will migrate cleanly with `db:push`.

  1593→## 19. Edge Cases & Gotchas
  1594→
  1595→### 19.1 Critical
  1596→
  1597→| # | Edge Case | Handling |
  1598→|---|-----------|----------|
  1599→| E1 | **Duplicate medicines from multiple findings** | When auto-filling from 2nd finding, skip medicines already in the list (match by `medicineId` from DoctorMedicine) |
  1600→| E2 | **Complaint deleted after being used in Rx** | Never hard-delete master data. Use soft delete (status=Inactive). PCo records keep the `coId` reference — snapshot the text at Rx creation time |
  1601→| E3 | **DoctorMedicine dose array empty** | If dose array is `[]`, show a plain text input instead of dropdown in Step 4 |
  1602→| E4 | **Prescription init when draft already exists** | Check for existing Draft prescription for the bookingId. If found, load it instead of creating new |
  1603→| E5 | **Concurrent editing** | Assistant and Doctor shouldn't edit same prescription simultaneously. Lock prescription when doctor opens it (or at minimum, show warning) |
  1604→| E6 | **Print with no data** | Each section in print is conditional — only shown if data exists |
  1605→| E7 | **Category deleted but complaints exist** | Complaints can exist without a category (categoryId nullable). Show them under "Uncategorized" in stepper |
  1606→

  1608→
  1609→| # | Edge Case | Handling |
  1610→|---|-----------|----------|
  1611→| E8 | **Mobile stepper** | On mobile, step indicator shows icons only (numbers). Step content is full-width scrollable |
  1612→| E9 | **Large findings list** | Findings dropdown should be searchable (typeahead) |
  1613→| E10 | **Many complaints** | Step 1 complaints should be searchable and grouped with collapsible categories |
  1614→| E11 | **Table with many rows/cols** | Tables should be horizontally scrollable on mobile |
