    35→    35→## 1. Executive Summary
    36→    36→
    37→    37→The current prescription system is a **flat single-page form** that creates a prescription in one shot. The legacy PHP system uses a **6-step AJAX stepper wizard** where two different roles (Assistant and Doctor) complete different steps. This plan rebuilds the entire prescription workflow to match the legacy system's UX while leveraging the modern Next.js stack.
    38→    38→
    39→    39→### Key Changes at a Glance
    40→    40→
    41→    41→| Aspect | Current (Broken) | Planned (Legacy Match) |
    42→    42→|--------|------------------|------------------------|
    43→    43→| Prescription creation | Single flat form | 6-step stepper wizard (AJAX, no page reload) |
    44→    44→| Roles | Doctor only | Assistant (Steps 1-2) + Doctor (Steps 3-6) |
    45→    45→| Complaints | None | C/O with multi-language (local + English) |
    46→    46→| Vitals | Flat fields in prescription | Step 2 — separate entry by assistant |
    47→    47→| Medicine timing | Booleans (morning/afternoon/evening) | Numbers (tablet count per time slot) |
    48→    48→| Medicine dose | Single string | JSON array of options (tag input) |
    49→    49→| Findings | None | NEW — auto-fill medicines by finding |
    50→    50→| Suggestions | Free text | Auto-linked from Category → Complaint → Suggestion hierarchy |
    51→    51→| Labels | No units, no showUnit toggle | Units + `showUnit` boolean per label |
    52→    52→| Tables | No custom templates | Doctor-built table templates with preview |
    53→    53→| Print | Basic template | Custom header OR full header image, C/O section, tables, next visit |

    58→    58→
    59→    59→### 2.1 The Two-Phase Workflow
    60→    60→
    61→    61→```
    62→    62→┌─────────────────────────────────────────────────────────────────┐
    63→    63→│                    PATIENT FLOW                                  │
    64→    64→│                                                                  │
    65→    65→│  Patient arrives → Sits OUTSIDE cabin → Goes INSIDE cabin       │
    66→    66→│                                                                  │
    67→    67→│  ┌──────────────────┐     ┌──────────────────────────────┐     │
    68→    68→│  │   ASSISTANT      │     │         DOCTOR               │     │
    69→    69→│  │   (Outside)      │     │         (Inside)             │     │
    70→    70→│  │                  │     │                              │     │
    71→    71→│  │ Step 1: Complaints│     │ Step 3: Diagnosis Tables    │     │
    72→    72→│  │ Step 2: Vitals    │     │ Step 4: Medicines           │     │
    73→    73→│  │                  │     │ Step 5: Suggestions          │     │
    74→    74→│  │                  │     │ Step 6: Finish & Print       │     │
    75→    75→│  └──────────────────┘     └──────────────────────────────┘     │
    76→    76→│                                                                  │
    77→    77→└─────────────────────────────────────────────────────────────────┘
    78→    78→```
    79→    79→
    80→    80→### 2.2 Multi-Language Dual-Field Pattern
    81→    81→
    82→    82→**Every user-facing text entity uses TWO fields:**
    83→    83→
    84→    84→```
    85→    85→┌─────────────────────────┬──────────────────────────┐
    86→    86→│  Field (Primary)        │  FieldEn (English)        │
    87→    87→├─────────────────────────┼──────────────────────────┤
    88→    88→│  "તાવો આવે છે" (Gujarati)  │  "Fever" (English)        │
    89→    89→│  "સરદી લાગે છે"          │  "Cold"                   │
    90→    90→│  "પેટમાં દુખાવો"          │  "Stomach Pain"           │
    91→    91→└─────────────────────────┴──────────────────────────┘
    92→    92→
    93→    93→Usage:
    94→    94→  - SELECTOR UI (stepper, dropdowns, tags) → Shows PRIMARY (local language)
    95→    95→  - PRINT OUTPUT (prescription PDF/print)  → Shows ENGLISH version
    96→    96→```
    97→    97→
    98→    98→### 2.3 Suggestion Auto-Linking Hierarchy
    99→    99→
   100→   100→```
   101→   101→Category (શરીર / Body)
   102→   102→  └── Complaint (તાવો / Fever)  ← Selected in Step 1
   103→   103→        ├── Suggestion 1: "Drink plenty of water"
   104→   104→        ├── Suggestion 2: "Take rest for 3 days"
   105→   105→        └── Suggestion 3: "Avoid cold food"
   106→   106→
   107→   107→  └── Complaint (સરદી / Cold)  ← Also selected in Step 1
   108→   108→        ├── Suggestion 1: "Steam inhalation 2x daily"
   109→   109→        └── Suggestion 2: "Warm water gargling"
   110→   110→
   111→   111→In Step 5: Only suggestions linked to SELECTED complaints appear.
   112→   112→```
   113→   113→
   114→   114→### 2.4 Findings → Medicine Auto-Fill
   115→   115→
   116→   116→```
   117→   117→Doctor creates Finding: "Viral Fever"
   118→   118→  └── Links 5 medicines to it:
   119→   119→        ├── Paracetamol 500mg — 1-0-1
   120→   120→        ├── Azithromycin 500mg — 1-0-0 (3 days)
   121→   121→        ├── Cetirizine 10mg — 0-0-1
   122→   122→        ├── Pan D — 1-0-0
   123→   123→        └── Multivitamin — 1-0-1
   124→   124→
   125→   125→During Rx Step 4: Doctor selects "Viral Fever" from dropdown
   126→   126→  → All 5 medicines auto-fill with their doses and timings
   127→   127→  → Doctor can modify any individual medicine before saving
   128→   128→```

   490→   490→## 5. The 6-Step Stepper Wizard
   491→   491→
   492→   492→### 5.1 Step Overview
   493→   493→
   494→   494→| Step | Title | Actor | Description |
   495→   495→|------|-------|-------|-------------|
   496→   496→| 1 | **Chief Complaints (C/O)** | Assistant | Select complaints from master (shown in primary/local language). Multi-select with search. |
   497→   497→| 2 | **Vitals & Labels** | Assistant | Enter patient vitals using Label Master. Weight, BP, Temperature + any custom labels. |
   498→   498→| 3 | **Diagnosis Tables** | Doctor | Add custom tables (ultrasound reports, lab data). Can use pre-built templates or create ad-hoc. |
   499→   499→| 4 | **Medicines (Rx)** | Doctor | Add medicines manually OR auto-fill via Findings dropdown. Edit any field. |
   500→   500→| 5 | **Suggestions / Advice** | Doctor | Suggestions auto-populated based on selected complaints (from Step 1). Click to select. |
   501→   501→| 6 | **Finish & Print** | Doctor | Review all data. Set next visit date. Save & Print. |
   502→   502→
   503→   503→### 5.2 Stepper UI Behavior
   504→   504→
   505→   505→```
   506→   506→┌─────────────────────────────────────────────────────────────┐
   507→   507→│  ① Complaints  →  ② Vitals  →  ③ Tables  →  ④ Rx  →  ⑤ Advice  →  ⑥ Finish  │
   508→   508→│  ═══════════     ────────    ────────   ───────   ────────    ────────  │
   509→   509→│  (completed)     (current)  (pending)  (pending)  (pending)   (pending)  │
   510→   510→└─────────────────────────────────────────────────────────────┘
   511→   511→
   512→   512→RULES:
   513→   513→- Steps 1-2: Visible & editable by ASSISTANT role
   514→   514→- Steps 3-6: Visible & editable by DOCTOR role
   515→   515→- All 6 steps visible as a progress bar at the top
   516→   516→- Current step content swaps below WITHOUT page reload (React state)
   517→   517→- Each step has a "Save & Continue" button that persists to DB via API
   518→   518→- Steps 1-2 are auto-saved when assistant submits
   519→   519→- Doctor sees read-only summary of Steps 1-2 at the top when entering Step 3
   520→   520→- Back navigation allowed (go back to previous step, data preserved)
   521→   521→- Steps are NOT strictly sequential for doctor — can jump to any step 3-6
   522→   522→```

   735→   735→## 6. Two-Phase Workflow (Assistant + Doctor)
   736→   736→
   737→   737→### 6.1 How It Works
   738→   738→
   739→   739→```
   740→   740→ASSISTANT FLOW:
   741→   741→1. Assistant opens their dashboard → sees "Pending Prescriptions" queue
   742→   742→2. Clicks on an approved/visited appointment
   743→   743→3. Lands on Step 1 (Complaints) of the stepper
   744→   744→4. Selects complaints, enters vitals (Steps 1-2)
   745→   745→5. Clicks "Submit to Doctor" → prescription saved with status "Draft"
   746→   746→6. Prescription appears in Doctor's queue
   747→   747→
   748→   748→DOCTOR FLOW:
   749→   749→1. Doctor opens their dashboard → sees prescriptions ready for completion
   750→   750→2. Clicks on a prescription → lands on Step 3 (Tables)
   751→   751→3. Steps 1-2 shown as READ-ONLY summary at top
   752→   752→4. Doctor completes Steps 3-6
   753→   753→5. On Step 6, clicks "Save & Print" → prescription finalized
   754→   754→```
   755→   755→
   756→   756→### 6.2 Assistant Queue Page
   757→   757→
   758→   758→- **Route:** `/dashboard/assistant/prescription-queue`
   759→   759→- **Lists:** All appointments with status `Approve` or `Visited` that don't have a prescription yet, OR prescriptions with status `Draft` (assistant completed Steps 1-2, waiting for doctor)
   760→   760→- **Sidebar entry:** Added to `assistant` role in sidebar-config.ts
   761→   761→
   762→   762→### 6.3 Doctor's Prescription Entry Point
   763→   763→
   764→   764→- **Route:** `/dashboard/doctor/prescriptions/new?bookingId=xxx`
   765→   765→- If booking already has a Draft prescription (assistant completed Steps 1-2), load that prescription and start at Step 3
   766→   766→- If no draft exists, create a new prescription and start at Step 1 (doctor does everything manually)
   767→   767→- Doctor can also start from appointment list: click appointment → "Create Prescription" → opens stepper

   785→   785→
   786→   786→1. **Master entry forms**: Always show BOTH fields. Primary language field is required, English field is optional (but recommended).

   788→   788→3. **Print output**: Always use ENGLISH fields. If English is empty, fall back to primary field.
   789→   789→4. **Snapshot records** (PMedicine, PLabel, PSuggestion, etc.): Store both versions at the time of prescription creation.

   914→   914→
   915→   915→```

  1555→  1555→## 18. Migration Strategy for Existing Data
  1556→  1556→
  1557→  1557→### 18.1 Morning/Afternoon/Evening: Boolean → Int
  1558→  1558→
  1559→  1559→```sql
  1560→  1560→-- Migrate PMedicine
  1561→  1561→UPDATE "PMedicine" SET "morning" = CASE WHEN "morning" = true THEN 1 ELSE 0 END;
  1562→  1562→UPDATE "PMedicine" SET "afternoon" = CASE WHEN "afternoon" = true THEN 1 ELSE 0 END;
  1563→  1563→UPDATE "PMedicine" SET "evening" = CASE WHEN "evening" = true THEN 1 ELSE 0 END;
  1564→  1564→
  1565→  1565→-- Migrate DoctorMedicine (was String type, values like "after food" or empty)
  1566→  1566→-- This is trickier — need to set reasonable defaults
  1567→  1567→UPDATE "DoctorMedicine" SET "morning" = 1 WHERE "morning" != '';
  1568→  1568→UPDATE "DoctorMedicine" SET "afternoon" = 1 WHERE "afternoon" != '';
  1569→  1569→UPDATE "DoctorMedicine" SET "evening" = 1 WHERE "evening" != '';
  1570→  1570→UPDATE "DoctorMedicine" SET "morning" = 0 WHERE "morning" = '';
  1571→  1571→UPDATE "DoctorMedicine" SET "afternoon" = 0 WHERE "afternoon" = '';

  1593→  1593→## 19. Edge Cases & Gotchas
  1594→  1594→
  1595→  1595→### 19.1 Critical
  1596→  1596→
  1597→  1597→| # | Edge Case | Handling |
  1598→  1598→|---|-----------|----------|
  1599→  1599→| E1 | **Duplicate medicines from multiple findings** | When auto-filling from 2nd finding, skip medicines already in the list (match by `medicineId` from DoctorMedicine) |
  1600→  1600→| E2 | **Complaint deleted after being used in Rx** | Never hard-delete master data. Use soft delete (status=Inactive). PCo records keep the `coId` reference — snapshot the text at Rx creation time |
  1601→  1601→| E3 | **DoctorMedicine dose array empty** | If dose array is `[]`, show a plain text input instead of dropdown in Step 4 |
  1602→  1602→| E4 | **Prescription init when draft already exists** | Check for existing Draft prescription for the bookingId. If found, load it instead of creating new |
  1603→  1603→| E5 | **Concurrent editing** | Assistant and Doctor shouldn't edit same prescription simultaneously. Lock prescription when doctor opens it (or at minimum, show warning) |
  1604→  1604→| E6 | **Print with no data** | Each section in print is conditional — only shown if data exists |
  1605→  1605→| E7 | **Category deleted but complaints exist** | Complaints can exist without a category (categoryId nullable). Show them under "Uncategorized" in stepper |
